## 单一口径

- 主表只有一个来源：`bench-merged-2026-11-08T02-55-02-172Z.md`。仓库里任何其他 C 数字（66.7% / 96.7%）都是旧批次，不得与主表混用。
- 旧 `latest-analysis.md` 与 10-31 报告的 6ms 类总耗时来自合并脚本计时缺陷；`merge-results.mjs` 现在要求 `BENCH_SUITE_STARTED_AT`，缺失时直接写“未记录”，不再用合并动作耗时冒充运行耗时。
- 消融臂 `Csingle`（单验证器）与 `Cstatic`（去调度）已实现并有 stub 烟测，但**尚未跑 live**。多验证器的现有 live 证据是 `C−loop − B`，不是 `Csingle`。
- 并发报告只有 stub；live 并发未验证。stub 的任务达标率不具参考意义，只用于观察成功率、排队与执行开销。

## 口径

- 达标只看固定裁判 `fixed-judge-rules-v2` 的 `evalScore ≥ threshold` 且无硬规则失败；平台自验分只作对照。
- 金标检索相关性由脚本按用例主题标注（agent 构建，非人工标注）。
- 合并报告只在各批运行均成功时生成；分两批运行时墙钟耗时不合并推算，用例定义、臂、裁判与模型必须一致。
- 上游单次模型请求默认 180 秒超时（`PLATFORM_MODEL_TIMEOUT_MS`）；2026-11-08 的选题重跑未出现超时失败。
