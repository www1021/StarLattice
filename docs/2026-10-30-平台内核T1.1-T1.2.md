# 2026-10-30 平台内核 T1.1 / T1.2 验收记录

## 做了什么

- T1.1：`server/platform/runtime/stateStore.ts` 初始化 8 张 `platform_*` 表（agents / tools / workflows / runs / run_steps / verify_results / loop_iterations / eval_tasks），提供工作流、运行、步骤、验证结果、循环迭代的读写方法。
- T1.2：JSON DSL 与编译器，6 类节点 `agent` / `tool` / `parallel` / `condition` / `loop` / `verify`；编译期做必填校验、全局 id 唯一、边合法性、拓扑排序、环检测、嵌套子流程展开、变量引用与作用域校验、条件表达式解析。
- 可运行的壳：`server/platform/runtime/executor.ts` 按编译计划执行，逐步写 `platform_run_steps`，验证节点写 `platform_verify_results`，循环轮次写 `platform_loop_iterations`；未接入真实 Agent 时使用确定性 stub（输出带 `mode: "stub"`）。
- API：`/api/platform/health`、`/api/platform/workflows`（list / save / get / validate）、`/api/platform/runs`（start / list / get / trace）。

## 怎么验证

- `npx tsc -p tsconfig.server.json` 通过。
- `npm run test:platform`：10 个用例通过（编译、环检测、引用顺序、条件分支、失败步骤、8 表初始化、主链路运行）。
- `npm run build` 通过（仅保留原有 chunk >500KB 警告）。
- 实跑 `PORT=8791 npx tsx server/index.ts` 后：
  - `GET /api/platform/health` → `tableCount: 8`，`builtinWorkflows: ["classroom-v1"]`。
  - `POST /api/platform/runs {"workflowId":"classroom-v1", ...}` → `status: succeeded`，12 条步骤记录。
  - `GET /api/platform/runs/:id/trace` → 验证分数 `0.62 → 0.74 → 0.86`，循环 2 轮 `[1, 0.62, 0.74]`、`[2, 0.74, 0.86]`。
  - 给 DSL 加一条 `report → retrieve` 的边再 POST，返回 400 并给出环路径。
