# 2026-10-30 画布节点契约（T1.10 前置冻结）

> 目的：在写 `WorkflowCanvasPage.tsx` 之前冻结"画布编辑什么、存回什么"，避免前端做完后跟内核返工。
> 契约版本：`1`，与 `GET /api/platform/node-types` 的 `version` 字段一致。改字段要升版本并同步本文件。

## 1. 渲染模型

| 约定 | 取值 | 说明 |
|---|---|---|
| 图模型 | `top-level-dag` | 画布只画顶层节点和顶层边 |
| 容器节点 | `collapsed` | `parallel / condition / loop` 各显示为一个节点 |
| 容器内部 | `list` | 子块（`branches / then / else / body`）在右侧抽屉里用列表编辑 |
| 边范围 | `edgeScope: top-level` | 连线只能连顶层节点；嵌套节点不画边 |
| 变量引用 | `${节点ID.字段}` / `${input.字段名}` | 节点 ID 全流程唯一，引用靠它定位 |

理由：DSL 的嵌套块不是自由连线，做成嵌套画布成本高、收益低；折叠容器已足够演示"编排"，且存回的 JSON 天然合法。

## 2. 节点字段（与 `/api/platform/node-types` 一一对应）

所有节点共用 `commonFields`：

| key | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | text | 是 | 唯一，`[A-Za-z0-9_-]+` |
| `title` | text | 否 | 画布显示名 |
| `description` | textarea | 否 | 说明 |

分类型字段：

| kind | 专属字段 | 子块 |
|---|---|---|
| `agent` | `agent`（必填，Agent ID）、`prompt`（支持引用）、`inputs`（JSON，支持引用） | 无 |
| `tool` | `tool`（必填，工具 ID）、`args`（JSON，支持引用） | 无 |
| `parallel` | 无 | `branches`（必填，可多） |
| `condition` | `when`（必填，表达式） | `then`（必填）、`else`（可选） |
| `loop` | `maxIterations`（必填，1–20，默认 2）、`while`（可选表达式） | `body`（必填） |
| `verify` | `verifier`（必填）、`rubric`（列表）、`threshold`（0–1，默认 0.8）、`inputs`（JSON） | 无 |

`agent` / `tool` / `verifier` 在 T1.3 注册中心上线前是自由文本，上线后改为下拉，字段名不变。

## 3. 表达式

- 只支持两种形式：`${引用}`（真值判断）和 `${引用} 运算符 值`。
- 运算符：`<` `<=` `>` `>=` `==` `!=`。
- 解析不了的写法在编译期报 `unsupported-expression`，画布应阻止保存。

## 4. 校验错误 → 节点定位

`POST /api/platform/workflows` 与 `/workflows/:id/validate` 失败时返回：

```json
{ "message": "DSL 校验未通过（1 项）：...", "issues": [{ "code": "reference-order", "path": "rehearse/student-weak", "message": "..." }] }
```

`path` 用 `/` 连接容器路径：顶层节点 path 就是 id，嵌套节点形如 `rehearse/student-weak`，节点字段错误会追加 `.when` / `.while`（如 `revise-loop.while`）。画布按 `/` 切段并去掉 `.字段` 后缀，取第一个命中的顶层节点 id 标红（`rehearse/student-weak` 落到容器 `rehearse`）；`edges[...]`、`inputs[...]`、`cycle` 一类没有节点归属的错误放横幅即可。`code` 建议映射成固定文案。

常见 code：`cycle`、`duplicate-node-id`、`unknown-edge-node`、`unknown-node-ref`、`reference-order`、`unknown-input`、`unsupported-expression`、`max-depth`、`invalid-loop-limit`、`invalid-threshold`。

## 5. 画布要用到的接口

| 用途 | 接口 |
|---|---|
| 取节点字段描述 | `GET /api/platform/node-types` |
| 加载工作流列表 / 详情 | `GET /api/platform/workflows`、`GET /api/platform/workflows/:id` |
| 保存 DSL | `POST /api/platform/workflows`，body：`{ "dsl": { ... } }` |
| 只校验不保存 | `POST /api/platform/workflows/:id/validate`，body 可带 `dsl` 覆盖已存版本 |
| 启动运行 | `POST /api/platform/runs`，body：`{ "workflowId": "classroom-v1", "input": {...} }` |
| 运行时上色 | `GET /api/platform/runs/:id/trace` → `steps[].path / status / nodeId` |

运行态上色规则：`steps[].path` 与画布节点 path 同构，取第一段（即顶层 `nodeId`）聚合；容器节点用内部步骤的汇总状态（失败优先，其次运行中，最后成功）。

## 7. 明确不做（画布侧）

- 不做嵌套画布、不做跨容器连线。
- 不做自动布局、撤销重做（P2）。
- 不做 Agent/Tool 参数的富表单；T1.3 上线前一律用 JSON 编辑器 + 字段描述渲染。
- 画布不负责执行；运行统一走 `/api/platform/runs`。

## 8. 验收

- `GET /api/platform/node-types` 返回 6 类节点，`canvas.model = top-level-dag`。
- `npm run test:platform` 中有契约一致性用例：6 类节点全覆盖、容器必须有子块、字段名必须是解析器接受的键。
