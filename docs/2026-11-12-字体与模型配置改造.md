# 字体渲染与模型密钥配置改造（2026-11-12）

两件事：界面字看起来发虚，以及模型与 API Key 写死在后端环境变量里、界面上没法配。

## 一、字体

### 为什么会糊

三个原因叠在一起，不是单一问题：

1. **全局用的是楷体**。`src/styles.css` 的 `:root` 上写着 `font-family: "KaiTi", "STKaiti", "楷体", serif`，Windows 的楷体是为印刷设计的，笔画末端细，在 12px 上下的小字号里会糊成一片。
2. **`text-rendering: geometricPrecision`**。这个值要求浏览器按几何精度排字、放弃像素对齐与字形微调，小字号下反而更虚。
3. **字号偏小**。改造前平台页有 141 处 `10.5px`、99 处 `11px`、74 处 `10px`，全站 9px 以下还有 16 处。楷体 + 9~11px 是最难看的组合。

### 改了什么

**字体栈换成系统 UI 无衬线**，和主流智能体一致（Windows 走 Segoe UI + 微软雅黑 UI，macOS 走 SF + 苹方）：

```css
--font-ui: "Segoe UI Variable Text", "Segoe UI", -apple-system, BlinkMacSystemFont,
  "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei UI", "Microsoft YaHei",
  "Source Han Sans SC", "Noto Sans CJK SC", sans-serif;
--font-mono: "Cascadia Mono", "Cascadia Code", "JetBrains Mono", "SFMono-Regular",
  Consolas, ui-monospace, Menlo, monospace;
```

`platform.css` 里 40 多处零散的 `system-ui, ...` 与 `ui-monospace, ...` 全部改成引用这两个 token；说课训练页那条写死楷体的 `.app-shell:has(.speak-workspace)` 也一起改掉。

**`text-rendering` 改成 `optimizeLegibility`**，恢复字形微调。

**字号整体上抬一档**（只动 12.5px 及以下，12px 以上不动，避免撑破紧凑布局）：

| 原值 | 新值 |
| --- | --- |
| 8 / 9 / 9.5 | 10.5 |
| 10 | 11 |
| 10.5 | 11.5 |
| 11 / 11.5 | 12 |
| 12 / 12.5 | 13 |

共 849 条规则、4 个样式文件。

**次要文字加深一档**：`color: var(--n-51)` / `color: var(--n-54)` 共 107 处换成 `--n-46`。这两档在白底上的对比度分别约 4.1:1 与 3.8:1，低于 AA 的 4.5:1；换到 46 档约 5.0:1。只改 `color:` 属性，不碰 `border-color` / `background-color`，边框层次不变。工作台的 `--wb-text-3` 同步从 51 调到 46。

## 二、模型与密钥

### 改造前

模型目录（`server/platform/models/catalog.ts`）里 6 个内置档案全部从环境变量读凭据：`QUEEN_ACCESS_KEY` / `QWEN_API_KEY` / `DASHSCOPE_API_KEY`、`QWEN_BASE_URL`、`QWEN_MODEL`。想换模型只有两条路：改 `.env` 再重启，或者往 `PLATFORM_MODEL_CATALOG` 里塞一段 JSON。界面上看不到也改不了。

对话链路（`qwenOpenAiClient.ts`）更是直接读 `process.env`，完全绕开模型目录。

### 存储

新增 `server/platform/models/userModels.ts`：

- 文件：`data/settings/models.json`（可用 `MODEL_SETTINGS_DIR` 覆盖目录），原子写（tmp + rename）。
- **API Key 用 AES-256-GCM 加密**：每条存成 `v1:<iv>:<tag>:<cipher>`。密钥是 `data/settings/model-key` 里 32 字节随机数，首次使用时生成，权限 0600。
- 密钥文件损坏时**不静默重建**，直接抛错并提示“已保存的密钥将无法解密”，避免悄悄丢掉用户的 Key。
- 读配置按文件 `mtime + size` 缓存，写入时立刻失效 —— 否则对话链路每次取密钥都要读一次磁盘。

`data/settings/` 不进版本库，属于本机私有配置。

### 接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/platform/models` | 列表 + `defaultModelId`，含 `origin` / `keySource` / `apiKeyHint` / `isDefault` |
| POST | `/api/platform/models` | 新增或更新自建模型；`apiKey` 留空表示沿用原密钥 |
| POST | `/api/platform/models/test` | 连通性测试，可传 `id`（用已存配置）或临时 `baseUrl/model/apiKey` |
| POST | `/api/platform/models/:id/default` | 设为默认 |
| DELETE | `/api/platform/models/:id` | 删除自建模型（内置的不允许） |

**脱敏规则**：接口永远不返回明文密钥，`apiKeyHint` 只给 `sk-abc…3f9a` 这种形式，且列表 UI 只显示「密钥已加密保存 / 来自环境变量 / 未配置」，hint 放进 `title`。`baseUrl` 只对自建模型回传（编辑要回显），内置模型保持不暴露 —— 这条是既有测试 `exposes the logical model catalog without leaking credentials` 守着的契约。

**连通性测试在服务端发请求**（`models/probe.ts`），不是浏览器直连：避免 CORS，也避免把密钥交给前端。上游报错会翻译成人话（401 → 密钥无效、404 → 地址可能少 `/v1`、429 → 额度或频率），错误体里的密钥会被替换成 `***`。

### 优先级链

三层，从上到下：

1. 设置面板里选的默认模型（`defaultModelId`）
2. 环境变量（`PLATFORM_LIVE_MODEL` / `QWEN_MODEL` / …）
3. 代码里的缺省值

`catalog.ts` 的 `platform-default` 档案把 `model` 设成 `defaultModelId` 指向的逻辑 id，再由 `aliasProfiles()` 继承那个档案的 provider / baseUrl / apiKey。所以“设为默认”不需要改动任何其他代码。

`qwenOpenAiClient.ts` 的 `getQwenModel` / `getQwenApiKey` / `getQwenBaseUrl` 三个函数改成先取 `platform-default` 档案，取不到才回落环境变量 —— 这一条很关键，否则设置里填了 Key，聊天仍然用旧配置。

### 界面

`AppearanceDialog` 拆成 `SettingsDialog`（外壳 + 左侧页签）+ `AppearancePanel`（原外观内容）+ `ModelsPanel`（新）。侧栏底部入口从「外观设置」改成「设置」。

模型页：

- 每行一条模型：名称、来源标签（默认 / 内置 / 环境变量 / 本机添加 / 缺密钥）、模型 id、供应商、密钥状态、操作（测试 / 设为默认 / 编辑 / 删除）。
- 「添加模型」展开内联表单，带 6 个供应商预设（阿里云百炼 / OpenAI / DeepSeek / Moonshot / 本地 Ollama / 自定义），选一个就带出接口地址与示例模型名。
- 成本档用三档圆角按钮，不用原生 `<select>`。

## 三、踩到的坑

## 八、连不上时先看模型名：拉取服务方真实可用模型

### 现象

点「测试连接」报 `接口地址可能不对，注意 baseUrl 通常要带 /v1。（Model not exist.）`。

这个提示会把人带偏。百炼（以及多数 OpenAI 兼容网关）在**密钥有效、模型名不对**时回的是 404 + `Model not exist.`；地址拼错反而是连不上或 404 页面。所以看到 404 就怪 baseUrl 是错的。

### 改动

1. **新增 `POST /api/platform/models/remote`**（`server/platform/models/remoteModels.ts`）：用表单里的地址与密钥请求 `GET {baseUrl}/models`，把 `data[]` / `models[]` / `output.models[]` / 裸数组四种结构统一抠成 ID 数组，去重排序、上限 300 条。密钥同样只在服务端用，浏览器拿不到。
2. **弹窗加「获取可用模型」**：模型名称这一行右侧一个轻量文字按钮（`.md-inline-action`），拉回来的列表作为下拉第一组「该密钥可用 · N 个」，预置组排在后面；重复的 ID 从预置组里剔掉，不会出现两行同名。
3. **拉回来发现当前模型名不在列表里**：直接清空并切回下拉，附一行红字说明，避免把永远调不通的名字存进档案。
4. **把错误归因拆开**：404 + 上游文本命中 `model not exist` / `model_not_found` / `invalid model` 时提示「模型名称不对，或这把密钥没开通该模型」，其余 404 才提示 baseUrl。
5. **顺手补密钥脱敏**：上游会自己把密钥截成 `****heck` 回显（我们原本只替换完整密钥，替不到这种残段），现在额外抹掉 `api key: xxx` 后面的内容与 `sk-` / `AIza` 开头的串。

### 验证

本地 Ollama（`http://127.0.0.1:11434/v1`）端到端跑通：点「获取可用模型」返回 `deepseek-r1:8b`，下拉显示「该密钥可用 · 1 个」，提示语为「当前这个模型在列表里」。假密钥打百炼返回 401 且报错文本里的密钥残段已被抹成 `***`。

新增 4 条单测：列表结构解析（四种形态 + 空值）、非法地址不发请求、404 模型不存在时不甩锅 baseUrl、密钥残段不外泄。`test:platform` 296/296。

## 九、下拉一滚就关，以及「常见供应商点完就不用填地址」

### 下拉被滚动关掉的真实原因

`Select` 与对话页的 `ModelPicker` 都在 document 上挂了 `scroll`（capture）监听，只要页面元素一滚就关面板，防的是弹窗滚动后面板跟触发器脱位。问题在于 capture 阶段能收到**面板自己内部**的滚动事件：滚轮翻列表、拖 `.md-sel-scroll` 的滚动条，全都算成「页面动了」，面板当场消失——所以表现为「我滚一下、或者点一下（拖动滚动条）就没了」。

修法是按事件源判断：

```ts
const handleScroll = (event: Event) => {
  const target = event.target;
  if (target instanceof Node && panelRef.current?.contains(target)) return; // 面板自己滚，不算
  setOpen(false);
};
```

另外给 `.md-sel-scroll` 和 `.composer-model-pop` 加 `overscroll-behavior: contain`，对话页那个面板补了 `max-height: min(420px, 62vh)` + 滚动，模型多了不再顶出屏幕。

CDP 实测（`dropdown-diag.mjs`）：开面板 → 滚轮滚 120px → 仍在；点分组标题 → 仍在；点搜索框 → 仍在；脚本滚动列表 → 仍在。

## 十、点页面别冒插入符；「史」字最后一捺被切平

### 「史」的捺为什么短

不是字体问题。`.nav-item span` 为了折叠动画写了 `overflow: hidden`，而它只有 `line-height: 13px` 高，微软雅黑的汉字本来就比行框高一点点，底部那 0.75px 的墨被裁掉了——笔尖正好在底部，一裁就变平。四个字里只有「史」收尾于捺笔，所以只有它看着短。

排查方式：4 倍截图后把 `overflow` 改成 `visible` 再拍一张，两张的墨迹边界差 12 个设备像素（≈0.75 CSS px），全在底部；像素对比一眼就能看出撇和捺的末端被同一条水平线切平。

改法是不动布局前提下给裁切框留活口：

```css
.nav-item span {
  overflow: hidden;              /* 老浏览器兜底 */
  overflow: clip;
  overflow-clip-margin: 3px;     /* 汉字撇捺有活口，折叠时照样裁干净 */
}
```

`overflow-clip-margin` 只影响裁切框，不影响布局，所以侧栏宽度、行高、折叠动画都没变。改完墨迹边界从 255 变成 271（设备像素），捺笔收尖恢复。

### 点一下页面就冒出闪烁的插入符

页面里没有任何 `contenteditable`，`designMode` 也是 off，实际可编辑的只有对话输入框；也就是说那根竖线要么是文本光标（I 形），要么是浏览器自己的文本选择。不管是哪种，界面都不该像文档：外壳默认不可选中、不显示插入符，只有真要复制的地方放行。

```css
.app-shell {
  caret-color: transparent;
  user-select: none;
}

/* 能复制的：对话正文、教案/报告正文、流式预览、代码、输入框 */
.message-bubble,
.message-bubble *,
.lesson-preview,
.lesson-preview *,
.speak-report-document,
.speak-report-document *,
.generation-stream-preview,
pre, code, input, textarea, select,
[contenteditable="true"],
.selectable {
  caret-color: auto;
  user-select: text;
}
```

要临时放开某块文字，给它加 `class="selectable"`。设置弹窗这类挂在 body 上的浮层不在 `.app-shell` 内，保持可选中，报错信息还能复制。

验证：侧栏拖选结果是空字符串；对话输入框仍然能聚焦、打字、选中文字，`caret-color` 计算值是正文颜色；整页截图无异常。

### 顺手修掉一个测试不隔离

`debugChat.route.test.ts` 的 `withServer()` 只清了 `QWEN_API_KEY` 等环境变量，没有隔离 `MODEL_SETTINGS_DIR`。开发机上真存了一条模型（`data/settings/models.json`），「没有模型凭据时降级为本地逐字回复」就会失败。改成每条用例用临时设置目录，结束后还原环境变量。`test:platform` 297/297。
