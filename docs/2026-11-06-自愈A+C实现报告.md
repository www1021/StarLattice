日期：2026-11-06  
范围：A（结构化 Agent 输出 + 模型诊断）+ C（Prompt 补丁晋升 + 诚实 stub / 验证）  
状态：**A+C 已完成并通过 live 验证；B（Function Calling 自愈）已完成，见 [`2026-11-06-自愈B工具调用报告.md`](./2026-11-06-自愈B工具调用报告.md)。**

## 1. 结论

旗舰 Self-Loop 已从「脚本按轮次抬分」改为「验证器发现错误 → 模型诊断并给出修正 → 平台执行修复并保留有效补丁」：

1. 首轮规划 Agent 选择 `gross`，关键指标与净额基准不一致，验证 **0.6854** 未通过。
2. 诊断 Agent 读取验证问题、指标、报告与检索到的口径规则，输出结构化诊断：`action=rewrite_agent`、`revenueBasis=net`、`promptPatch=...`，置信度 **0.98**。
3. 平台按模型选择的口径重算并重写报告，复核 **0.95** 通过（阈值 0.70）。
4. 有效补丁晋升为 `business-planner` **v1 → v2**，v1 快照保留。
5. 第二次运行直接采用 v2：规划首轮选择 `net`，**0 轮循环、首验 0.9 通过**。

需要明确的叙事边界：**验证器负责发现错误，模型负责诊断和修复，平台负责执行与保留有效变更。** 不是「模型自己发现了错误」，也不是「脚本按轮次抬分」。

## 2. 实现内容

### A. 结构化 Agent 输出与模型决策

- Agent 节点支持 `outputFormat: "json"`、`outputContract`（必填字段 / 枚举）与 `stubOutput`。
- 诊断 Agent 输出固定结构：`rootCause`、`evidence`、`action`、`revenueBasis`、`retrievalQuery`、`promptPatch`、`confidence`。
- Self-Loop 控制器优先消费模型动作（`rewrite_agent` / `swap_agent` / `retrieve`）；动作不可识别时回退到启发式完整链路（证据缺口 → 补充检索，连续停滞 → 换 Agent）。
- 运行记录标注 `决策来源：模型诊断 / 启发式`，并记录补丁是否应用。

### C. 补丁晋升、回滚与诚实验证

- `promoteToAgent` 把通过验证的 `promptPatch` 写入目标 Agent 新版本；旧版本快照保留，`rollbackAgent` 可回滚。
- `validatePromptPatch` 拒绝包含 4 位以上非年份数字或「参考答案」字样的补丁（测试覆盖 `42290` 泄漏场景），并要求补丁长度在 20–800 字之间。
- stub 打分为**内容驱动**：同一份产物无论第几次验证都得到同一分数；stub 置信度上限 0.50，并显式写入「stub 演练，不能作为自愈证据」。
- `number_match` 失败会把总分压到阈值以下，形成硬门禁。
- 新增 `number_match.anchors`：只核对关键指标标签后的首个数字，忽略序号、占比、环比、单项毛利率等派生数字；不配置 anchors 时保留旧的严格模式。
- 修复内置工作流引用示例资料包 id 时检索落空的问题：检索前把包 id 解析到已导入的同名知识库。

## 5. 诚实边界与残余风险

1. **不是「模型自己发现问题」**：问题由确定性验证器发现；模型负责根因诊断、动作选择与补丁撰写。
2. **锚点验证只覆盖关键指标**：`销售额基准`、`销货成本`、`毛利额`、`毛利率`、`净销售额`、`退款额`。派生数字和序号被有意忽略，因此它不是「全文数值证明」；非锚点位置的错误数字仍可能漏检。
3. **样本量有限**：live 仅验证 1 次成功自愈 + 1 次复用确认，模型为 `qwen3.8-flash`，未做多次重复与方差统计；不能据此宣称稳定命中率。
4. **补丁校验是防线不是证明**：当前只拦截 4 位以上非年份数字与「参考答案」字样，3 位数字、百分比等答案形态仍可能绕过；也无法证明补丁在所有输入下都正确。生产使用仍需人工复核。
5. **stub 不作为自愈证据**：stub 分值仅由内容决定、置信度上限 0.50，并在问题清单中显式标注。
6. **非旗舰流程仍保留脚本化演示**：`business-map-v1` 是固定模板链路，不作为模型自愈证据；对外演示应使用 `business-analysis-v1`。
7. **B 已完成**：诊断 Agent 已开启 `toolCalling`，自主调用知识库与 MCP 工具后再输出诊断；证据与边界见 [`2026-11-06-自愈B工具调用报告.md`](./2026-11-06-自愈B工具调用报告.md)。本报告中的 A+C 运行仍保留，用于对比「预填上下文诊断」与「模型自主查证诊断」。

## 6. 复现

```bash
cd StarLattice
PLATFORM_LIVE_AGENTS=1 PORT=8791 npx tsx server/index.ts

curl -s -X POST http://127.0.0.1:8791/api/platform/runs \
  -H 'Content-Type: application/json' \
  -d '{"workflowId":"business-analysis-v1","input":{"question":"按订单销售额口径看一下本期区域与品类毛利，为什么下滑？","source":"data/demo/sales.csv"}}'
```

当前演示环境已晋升到 v2，直接运行会首验通过。要复现完整自愈链路，先把规划 Agent 回滚到 v1：

```bash
curl -s -X POST http://127.0.0.1:8791/api/platform/agents/business-planner/rollback \
  -H 'Content-Type: application/json' -d '{"version":1}'
```

首次运行应看到 `initialScore < threshold`、1 轮循环后 `finalScore >= threshold`、晋升 `business-planner`；再次运行应看到 `iterations=0` 且首验通过。
