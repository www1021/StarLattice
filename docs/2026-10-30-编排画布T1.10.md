## 2. 交互设计

- **顶层 DAG**：只渲染 `definition.nodes` 与顶层 `edges`；`parallel / condition / loop` 在画布上折叠成单卡片。
- **编辑**：点击节点打开右侧浮层抽屉；字段来自 `node-types` 契约，含 JSON / 列表 / 数值校验；容器内部步骤以列表展开编辑，可增删 agent/tool/verify 子步骤。
- **连线**：拖 Handle 连线；选中节点后从工具栏添加节点会自动连一条边；Delete/Backspace 删除节点或边并同步 DSL。
- **保存**：`POST /api/platform/workflows`，返回编译统计；校验失败时把 `issues[].path` 映射到顶层节点（取路径中第一个命中的顶层 id），节点卡片红框并可在横幅点击定位。
- **运行**：弹窗中按 `workflow.inputs` 生成运行参数表单（string/number/boolean/object），保存后 `POST /runs` 并拉取 `GET /runs/:id/trace`；展示状态、耗时、步骤数、最终评分、循环轮次、验证结果、执行轨迹。
- **状态着色**：trace 步骤按 `path` 前缀聚合到顶层节点，成功/失败/运行中在节点卡片右上角显示状态点。

## 4. 已知边界（后续任务）

- **不写回位置**：拖动节点只改变画布坐标，DSL 不存布局；重新加载按分层算法重排。
- **工作流级配置**：画布只编辑节点；`name / inputs / version` 仍需接口或后续设置面板。
- **注册中心**：`agent / tool / verifier` 字段暂为字符串输入，T1.3 上线后改成真实下拉。
- **监控台**：trace 为只读列表；单步输入输出、错误堆栈、单节点重跑、运行中实时刷新归 T1.11。
- **校验覆盖**：前端只展示后端返回的 issues；前端不做本地规则校验，避免规则双写。
- 布局为简单分层算法，长流程需手动缩放/平移；自动布局与撤销重做按 TODO 定为 P2。

## 5. 30 秒演示脚本

1. 侧边栏打开「编排画布」，看到主链路 7 个节点与「节点契约 v1 · 6 类节点」。
2. 点「自循环修正」，抽屉里把继续条件改为 `< 0.95`、最大轮次改为 3，保存。
3. 点「运行」→ 填课题/学科/年级 → 运行；弹窗展示 0.62 → 0.74 → 0.86 → 0.95、3 轮循环、14 条执行记录。
4. 关闭弹窗，画布节点全部变绿，底部徽标显示「上次运行 成功」。
