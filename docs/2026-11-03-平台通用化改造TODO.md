## 验收一句话

> 新增一个业务场景，不需要改平台引擎代码。

判断标准：只通过注册中心、编排画布、知识库、验证规则就能完成新场景；引擎代码零改动。

## 0. 现状判断（已核对代码）

- 引擎已经是领域无关的：调度器只认能力标签 / 可用度 / 优先级，编译器只认 DAG / 作用域 / 循环，执行器只认节点类型，验证器只认规则 / Rubric / 证据。
- 真正让平台显得“教育专用”的是四层内容：内置 Agent、内置工具、内置流程与模板、界面默认文案。
- `server/qwenOpenAiClient.ts:490` 的“师范生实训平台”提示词是教育聊天应用的默认值，平台 live 路径都显式传了 system，**不要全局改**，否则会把教育场景的聊天人设改坏。
- 种子数据使用 `ON CONFLICT DO NOTHING`，新增 Agent / 工具不会覆盖已有编辑。

## 风险与边界

- **不要全局改** `server/qwenOpenAiClient.ts:490`：它是教育聊天应用默认人设，平台 live 调用不走它。
- **不要改仓库名、数据库名**：只改展示文案，避免破坏 import 与已有数据；npm 包名已随产品更名为 `starlattice`（不参与运行时引用）。
- **不要删教育内容**：教育是“深度”证据，经营分析是“广度”证据。
- **通用 Agent 能力标签不要和教育标签重叠**：否则调度器可能改派教育节点，破坏已有基准。
- **不做**：插件市场、安装/卸载、动态加载代码、顶层 output schema、细粒度 RBAC。
- **已有本地数据库**中的旧 Agent 仍显示 `classroom-llm`：只影响展示，可不迁移；如需统一，手动更新该字段，不写自动迁移。
