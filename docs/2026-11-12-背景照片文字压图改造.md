# 背景照片重做：原图直出 + 局部渐变蒙版 + 文字压图

## 一、为什么重做

上一版（11-12 上午）的做法是「照片 + 薄纱 + 磨砂玻璃卡」，观感上确实一体化，但违背了几条基本原则：

| 原来 | 问题 |
| --- | --- |
| `.app-photo { filter: blur(8px) saturate(1.04) }` | 整张图被全局虚化，照片细节全丢，只剩色块 |
| `linear-gradient(--app-photo-veil-color)` 铺满全屏 | 整张图被压了一层白/黑，画面不通透 |
| 深色主题 `brightness(0.56)` | 直接把照片压暗一半 |
| 磨砂玻璃卡 alpha 0.65 | 卡片是一块块半透明白板，压在照片上像塑料膜 |
| `.workspace::before` 中央柔光 | 又一层大范围的径向洗白 |

目标改成：**照片一个像素都不动，可读性由文字自己那块局部蒙版解决。**

## 二、新的四层结构

```
.app-photo            照片原图，无 filter、无薄纱、无 brightness
.app-photo-cutout     主体抠图（可选，只在「主体分层」模式下出现）
.app-shell            透明外壳
  └ 文字容器 @before  局部羽化蒙版：核心贴住文字盒，向外渐隐到全透明
```

### 1. 照片层原图直出

```css
.app-photo {
  position: fixed;
  inset: 0;
  background-image: var(--app-photo);
  background-size: cover;
  background-position: center;
  opacity: 0;                       /* 只受透明度滑杆控制 */
  transition: opacity 240ms ease;
}
html[data-photo="on"] .app-photo { opacity: var(--app-photo-opacity); }
```

`filter`、`transform`、`brightness` 全部删掉，深色主题也不再压暗。CDP 实测 `getComputedStyle(.app-photo).filter === "none"`。

### 2. 局部渐变蒙版

令牌收在 `html[data-photo="on"]` 上，浅色用白、深色用暗，其余不动：

```css
html[data-photo="on"] {
  --mask-tint: var(--rgb-surface);
  --mask-core: 0.9;          /* 文字正下方的浓度 */
  --mask-soft: 0.68;         /* 小挂件的浓度 */
  --mask-feather-x: 20px;    /* 左右渐隐宽度 */
  --mask-feather-y: 16px;    /* 上下渐隐宽度 */
}
```

蒙版不是渐变底色，而是给气泡/输入框加一层 `::before`，再用两向渐变做遮罩求交，得到「中间实、四边虚」：

```css
html[data-photo="on"] .message-bubble {
  border-color: transparent;
  background: none;
  box-shadow: none;
  backdrop-filter: none;
  isolation: isolate;
}

html[data-photo="on"] .message-bubble::before {
  position: absolute;
  z-index: -1;
  inset: 0;                                  /* 关键：向内羽化，不做外扩光晕 */
  content: "";
  border-radius: 26px;
  background: rgba(var(--mask-tint), var(--mask-core));
  backdrop-filter: blur(16px) saturate(1.04); /* 雾面玻璃，不是色块 */
  -webkit-mask-image:
    linear-gradient(to right, transparent, #000 var(--mask-feather-x), #000 calc(100% - var(--mask-feather-x)), transparent),
    linear-gradient(to bottom, transparent, #000 var(--mask-feather-y), #000 calc(100% - var(--mask-feather-y)), transparent);
  mask-image: /* 同上 */;
  -webkit-mask-composite: source-in;
  mask-composite: intersect;
}
```

**踩坑（值得记）**：一开始写成 `inset: -20px -26px`，想让光晕长到盒子外面去。结果 `.conversation` 有 `overflow-y: auto`（overflow-x 随之变成 auto），外扩的 26px 全被裁掉，视觉上就变成「一刀切」的硬边白块——羽化等于没做。改成 `inset: 0`、渐变往里收，问题消失。**要给某个被滚动容器包住的元素做外发光，先确认容器不会裁。**

侧栏不是小盒子，整列都是文字，所以只做右边缘渐隐，和内容区接上：

```css
html[data-photo="on"] .sidebar {
  background: linear-gradient(90deg,
    rgba(var(--mask-tint), var(--mask-core)) 0%,
    rgba(var(--mask-tint), var(--mask-core)) 56%,
    rgba(var(--mask-tint), calc(var(--mask-core) * .52)) 82%,
    rgba(var(--mask-tint), 0) 100%);
  box-shadow: none;
  backdrop-filter: none;
}
```

开场标题单独一块径向软蒙版，只包住标题和说明文字，`inset: -18px -6px`、`radial-gradient(56% 126% at 26% 50%, …)`，深色主题靠它把白字托起来。

### 3. 两种融合模式（二选一）

面板里的「融合方式」两张卡，对应 `<html data-photo-blend="soft|layered">`：

- **柔和融合（默认，推荐）**：照片清晰，文字容器用上面那套羽化蒙版，标题额外带一圈紧贴笔画的光晕（`text-shadow` 四层，从 0.95 到 0.32）。光晕跟着字形走，不是一大片白斑。
- **主体分层（高级）**：`<html data-photo-blend="layered">` 打开一个固定在视口的 `.app-photo-cutout` 图层（`background-image: var(--app-photo-cutout)`，和照片同一套 cover 几何），z-index 压在标题之上、可点控件之下：

```css
.app-photo-cutout { position: fixed; inset: 0; z-index: 3; pointer-events: none; display: none; }
html[data-photo="on"][data-photo-blend="layered"] .app-photo-cutout { display: block; }
html[data-photo="on"][data-photo-blend="layered"] .hero { z-index: 1; }
html[data-photo="on"][data-photo-blend="layered"] .composer-stack { z-index: 4; }
```

抠图由用户上传透明 PNG（压到 1600px 走 PNG 保留 alpha）。**没有直接接 SAM**：SAM ViT-B 权重约 375MB，还要 onnxruntime-web 或一个 Python 服务常驻，对一个纯本地前端来说代价太大，而且用户机器上已经有现成的抠图工具。接口留好了：换成 SAM 输出同一张透明 PNG 就能直接替换。

### 4. 文字仍然是文字

- 照片模式下没有再包任何遮罩层，`user-select` 恢复默认，标题、气泡正文都能拖蓝、双击取词；
- 输入框 `caret-color` 是正文色（实测 `rgb(34,35,37)`），能正常输入、光标闪烁；
- 只有「不是文字的地方」继续压着 `caret-color: transparent`（点空白、点卡片不会冒出一根竖线）。

### 5. 混色开关

「标题与画面混色」打开后：

```css
html[data-photo="on"][data-title-blend="blend"] .hero h1 {
  color: #fff;
  mix-blend-mode: difference;
  text-shadow: none;
}
```

照片亮处的字自动变深、暗处变亮，是真的跟画面混色而不是硬贴。

这里有个必须处理的坑：`mix-blend-mode` 只能跟**同一个栈上下文里、它下面的内容**混色。`.workspace` 平时带 `position: relative; z-index: 1`，自成一层，混合背景就只剩 `.workspace` 自己的透明底，白字混出来还是白的（实测过，字是死的白）。所以混色模式下要把这一层退回：

```css
html[data-photo="on"][data-title-blend="blend"] .workspace {
  z-index: auto;
}
```

退回后 `.workspace` 仍然排在 `.app-photo`（z-index 0）之后绘制，整体层级不变，混色才会落到根层那张照片上。实测标题在浅蓝天空上变成深色、可读，侧栏和输入框的层级没有受影响。

这个开关只在对比强烈的照片上好看，所以默认关闭，并且和蒙版互斥：开了混色就把标题蒙版关掉，否则是在跟自己的蒙版混色。

## 三、面板改动

`src/features/theme/appearance.ts` 的 `Appearance` 增加三个字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `photoBlend` | `"soft" \| "layered"` | 融合方式 |
| `cutout` | `string \| null` | 主体抠图 data URL |
| `titleBlend` | `boolean` | 标题是否用 mix-blend-mode |

`applyAppearance()` 同步写 `data-photo-blend`、`data-title-blend`、`--app-photo-cutout`。默认透明度从 72 调到 86（照片不再被薄纱压着，需要更实的底）。

`AppearancePanel` 加了融合方式两张卡、混色开关、抠图上传（含 PNG 说明），样式是 `theme.css` 里的 `.ap-modes / .ap-mode / .ap-switch / .ap-cutout`。

  - `photo-soft-light` / `photo-soft-dark`：照片清晰、侧栏右缘渐隐、标题与输入框为羽化托底；

  - `photo-title-blend`：混色模式下标题取画面颜色；
  - `photo-layered`：树枝抠图盖住标题右段，形成前后层次；
  - `photo-chat-light`：对话态气泡羽化托底、正文清晰；
  - `page-workbench-* / page-canvas-light / page-knowledge-light`：面板型页面不脏。
- CDP 断言：`.app-photo` 的 `filter: none`、`transform: none`；标题可选中（`getSelection()` 拿到了「今天想完成什么教学任务？」）；输入框 `caret-color` 非透明。

## 五、取舍

- **面板型页面（工作台/画布/知识库）仍然有半透明底**：这些页面整屏都是卡片，全靠透出照片会看不清。做法是把 `--glass-a` 提到 `calc(0.99 - opacity * 0.2)`（92% 时约 0.81），照片在缝隙和四周照样清楚，卡片自己够实。这是「照片原样」和「节点小字可读」之间的折中，写在 `theme.css` 的照片段头部。
- **深色主题的蒙版是暗的**：白字要立住，局部就得压暗。这是局部，不是整幅——照片在蒙版之外一点没动。
- **主体分层需要现成抠图**：见上文，SAM 的接入点已留。

## 十一、把「一块块底色」彻底撤掉（对齐 IDEA 的照片背景观感）

### 诉求

用户拿 IDEA 的照片背景截图对比：内容直接写在照片上，没有额外的背景色块。而我们的工作台每张卡片还是一块 80% 不透明的深灰，一眼就是「纸片压在照片上」。

### 为什么之前是「玻璃卡」

上一版的路子是：照片原图直出，可读性交给每块文字的羽化蒙版。对话页好用，但面板型页面（工作台/画布/知识库/监控）整屏都是卡片，每张卡都要托底，于是就变成满屏半透明色块——照片全被糊住了，跟「直接在照片上写内容」是两件事。

结论：**托底只能用在「字很少的地方」（对话页的标题、输入框），不能用在「整页都是卡片」的地方**。后者必须走「无底 + 文字自带对比」。

### 做法

**1. 面板底全部归零，用一个开关控制**

`styles.css` 里 243 处、`platform.css` 里 86 处都是这种写法：

```css
background: rgba(var(--rgb-surface), 0.62);
```

直接改值会波及没有照片的常态，所以批量改成乘一个系数：

```css
background: rgba(var(--rgb-surface), calc(0.62 * var(--panel-alpha, 1)));
```

默认 `1`，数值不变，常态观感一个像素没动（已截图对比 `plain-workbench-light.png`、`plain-canvas-light.png`）。照片模式下：

```css
html[data-photo="on"] .workspace {
  --panel-alpha: 0;
}
```

变量是继承的，所以整棵树里的「半透明白底」同时消失，只剩 `border-color: var(--glass-edge)` 那一圈淡描边划出结构。

弹窗、菜单这些必须盖住背景的浮层单独调回 1：

```css
html[data-photo="on"] .platform-modal,
html[data-photo="on"] .registry-modal,
html[data-photo="on"] .knowledge-popover,
html[data-photo="on"] .platform-flow-menu,
html[data-photo="on"] .platform-more-menu,
html[data-photo="on"] .growth-record-modal {
  --panel-alpha: 1;
}
```

**2. 可读性改由文字自己承担**

新增 `--halo-rgb`（浅色主题 = 白，深色主题 = 黑），配两级光晕：

```css
--ink-halo:    0 1px 2px rgba(var(--halo-rgb), .92), 0 2px 8px rgba(..., .7), 0 0 16px rgba(..., .42);
--ink-halo-sm: 0 1px 2px rgba(var(--halo-rgb), .86), 0 1px 6px rgba(..., .62), 0 0 12px rgba(..., .38);
```

白主题是「白雾托黑字」，深色主题是「黑雾托白字」，跟对话页标题用的是同一套逻辑。挂载点：

- `.wb`（工作台全部文字）
- `.platform-canvas`、`.knowledge-workspace`、监控/注册/报告/进化几页的根
- `.composer`（输入框内的工具条）

**3. 浅色主题单独加宽**

黑字压在照片暗部（山体、夜景）时，3 层白雾不够，会直接沉进去。浅色主题的 `--ink-halo` 加到 4 层、最外圈 16px：

```css
html[data-photo="on"][data-theme="light"] {
  --ink-halo: 0 0 2px rgba(255,255,255,.96), 0 0 7px rgba(...,.9),
              0 1px 2px rgba(...,.88), 0 2px 16px rgba(...,.6);
}
```

顺带把 `--wb-text-2 / --wb-text-3`（时间、版本号这些次级文字）从 39%/46% 灰提到 15%/21%，否则直接看不见。

**4. 剩下三种「还该有一点底」的地方**

| 位置 | 底 | 理由 |
| --- | --- | --- |
| 画布节点 `.platform-node` | 34% | 交互控件，一行十几个字，全透会散架 |
| 画布容器/面板 | 8%~16% | 同上，但要压到几乎看不出 |
| 对话输入框 / 气泡 | 16% / 14% | 只留一层「这里有块面」的暗示，主要靠 1px 描边 |
| 侧栏 | 90%（右缘渐隐） | 导航区，IDEA 的侧栏也是实底 |

对话页原来的托底是 90%，在深色主题下就是一大块近乎不透明的深灰——这正是用户说的「明显还有一个深灰色的背景」。现在降到 14~16%，同时删掉 `backdrop-filter`（它会糊掉照片，违背「原图清晰」）。开场标题那块 `radial-gradient` 托底直接删掉，靠 `--ink-halo` 立在照片上。

### 已知短板

- **浅色主题 + 明暗跨度极大的照片**（上半蓝天、下半黑山这种）是天然最差组合：黑字在白字光晕里勉强能读，但不如深色主题干净。深色主题（IDEA 那种）效果最好。
- 照片的白色主体（人、云、墙）落到文字上时会「吃掉」文字。无底方案无解，只能换图或改用「主体分层」。
