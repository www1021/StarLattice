# 外观主题与变量引用改造（2026-11-11）

## 一、输入变量：数据来源下拉 + 浮层引用选择器

### 改之前的问题

- 「数据来源」是一个图标按钮，点一下在「固定值 / 引用」之间来回切，看不出当前是什么模式。
- 引用面板内联在表格行下面，把整行撑开、面板宽度跟着节点栏走，长字段全被截断。

### 改之后

- 数据来源变成原生 `select`，两个选项：`输入` / `引用`。选 `引用` 时右侧换成「选择变量」按钮，并自动弹出面板；选 `输入` 时清空引用值、回到固定值输入框。
- 引用面板改为挂在 `document.body` 上的浮层（`position: fixed`，宽 318px），锚点是这一行的「数据来源」格子：
  - 默认向下弹，`top = min(rect.bottom + 6, innerHeight - 240)`；右边不够就往左收，左边至少留 8px。
  - 宿主容器滚动 / 窗口缩放时重新定位，点外部或 Esc 关闭。
  - 触发按钮自己负责开关，所以外部点击判定会把锚点排除掉，避免「刚点开就被关」。
- 面板内容按腾讯云工作流的三段式分组：
  1. `节点输出变量`：上游每个节点一行，带类型色块图标 + 名称 + 右箭头；
  2. `工作流级变量`：`workflow.inputs` 那一组（原来叫「工作流输入 / 启动参数」）；
  3. 应用级变量目前系统里没有这个概念，所以整段不渲染 —— 不造假分区。
- 下钻流程：节点 → 字段 → 子字段（对象 / 数组）→ 叶子点击即写入。头部左侧是「‹ 返回上一步 + 当前层级名」，右侧 `改为固定值` 与关闭。
- 搜索框在第一层跨全部节点找叶子，直接给「字段路径 + 所属节点」；进到某一层后只在当前层过滤。
- 引用框里只显示表达式主体：`${input.topic}` 显示成 `input.topic`，完整值放 `title`，省下 4 个字符的宽度。
- 提示词区的「插入变量」复用同一个 `VarPicker`，锚点换成那颗按钮，插入位置仍然跟随光标。

### 相关文件

- `src/features/platform/NodeInspector.tsx`：`InputSection`、`VarPicker`（新增 `refSections` / `useFloatPosition`）、`refLabel`。
- `src/features/platform/platform.css`：`.ni-ref-float*`、`.ni-var-source-select`；旧的 `.ni-ref-menu / -item / -cascade / -crumb` 一批样式已删除。

## 二、主题系统

### 为什么不是「再加一层覆盖样式」

三份样式表里写死了 579 个颜色，逐个写深色覆盖不现实。做法是把颜色先在构建期抽象成变量：

1. `scripts/theme-migrate.mjs`（一次性）
   - 扫描 `styles.css` / `platform.css` / `workbench.css` 里的十六进制色；
   - 按 HSL 分类：低饱和或暖灰（色相 20–52、饱和度 ≤30）算中性色，其余算强调色；
   - 中性色按明度分档成 `--n-<明度>`（33 个），强调色原值保留成 `--a-<hex>`（186 个）；
   - 输出 `src/styles/theme-tokens.css`，同时把样式表里的字面量替换成 `var(--...)`。
2. `scripts/theme-migrate-rgba.mjs`（一次性）
   - 处理 `rgba()` 叠层：亮且中性 → `rgba(var(--rgb-surface), a)`；暗且中性 → `rgba(var(--rgb-shadow), a)`；
   - 亮且有彩色倾向（浅绿/浅红/浅米）→ `color-mix(in srgb, var(--a-<最近强调色>) <a>%, transparent)`，让浅色薄层在深色下自动变暗色调；
   - `color` / `text-shadow` 一律不动，避免白字压品牌色被翻成深色。

### 两套主题

| 主题 | 页面底 | 侧栏 | 说明 |
| --- | --- | --- | --- |
| 白（默认） | `#ffffff` | `#f7f7f8` | 中性偏冷，正文 `--n-12`，接近常见聊天智能体的白 |
| 深色 | `hsl(220 9% 8.5%)` | `hsl(220 9% 11.5%)` | 明度按分段锚点翻转，表面 / 边框 / 文字各自落在舒服区间 |

> 原来的「暖纸」主题已下线：`ThemeMode` 只剩 `light | dark`，老数据里存着 `"paper"` 的会直接回落白色。删的时候要连带清掉 `styles.css` 末尾那段 `/* ===== 素纸主题：外壳与侧栏 ===== */`，它排在文件最后，会把选中态刷回白底棕字。

深色不是简单反色：`darkLevel()` 用一组锚点把明度 100→10、88→19、42→69、12→92 地映射，表面压到 10–27%、边框 19–26%、正文 86–93%，层次和浅色一致。强调色在深色下整体提亮（L≤45 的 +26，L≥88 的浅色调转成暗色块），所以标签、选中态不会糊。

### 侧栏选中态

只给被点中的那一条垫一层中性色，不掺品牌色：

| token | 白 | 深色 |
| --- | --- | --- |
| `--nav-active-bg` | `rgba(17,17,19,.075)` | `rgba(255,255,255,.09)` |
| `--nav-hover-bg` | `rgba(17,17,19,.045)` | `rgba(255,255,255,.05)` |
| `--nav-active-fg` / `--nav-active-icon` | `--n-12` / `--n-21` | `hsl(220 6% 96%)` / `93%` |

`.nav-item-active` 只写 `background + color + font-weight`，无描边无阴影；图标跟着文字提亮，不再单独染绿。

主按钮（新建）跟主题走，不固定品牌色：`--cta-bg / --cta-bg-hover / --cta-fg / --cta-border / --cta-shadow` —— 白主题是白底 + `#e3e3e6` 细描边 + 1px 投影的浮起块，深色是 `hsl(220 9% 16%)` 底 + `23%` 描边。这样侧栏里只有「选中项」和「新建」两个灰阶层级，不存在一整块橙色。

### 强调色：一套令牌顶掉品牌橙

原来的橙（`--a-a8552c` 家族，全站 94 处）是固定色，白主题、深色主题都是同一块暖橙，跟"界面跟主题走"直接冲突。现在改成一个会翻面的强调色：

| token | 白 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--accent` | `#1b1c1f` | `hsl(220 6% 93%)` | 实心按钮、激活文字、选中描边 |
| `--accent-strong` | `#000000` | `#ffffff` | hover / 加深 |
| `--accent-soft` | `rgba(17,17,19,.06)` | `rgba(255,255,255,.08)` | 淡染底（标签、选中行、提示块） |
| `--accent-line` | `rgba(17,17,19,.14)` | `rgba(255,255,255,.16)` | 配套描边 |
| `--chip-bg` / `--chip-fg` | `#ececee` / `#3f4146` | `rgba(255,255,255,.1)` / `hsl(220 6% 90%)` | 图标块 |
| `--edge-idle` / `--edge-active` / `--edge-running` | `#cfd0d4` / `#1b1c1f` / `#b8760a` | `hsl(220 8% 30%)` / `hsl(220 6% 88%)` / `#d9a559` | 画布连线 |

填充按钮本来就用 `color: var(--n-99)` 做字色，而 `--n-99` 在深色下是深底，所以换成 `--accent` 之后对比度自动成立，不用逐个补 `color`。

图标块全部收口到 `--chip-bg/--chip-fg`：调色板项、画布节点头、检查器头部、引用选择器的小节点图标、工作台步骤圆点。原来这些是 JSX 里 `style={{ background: spec.accent }}` 的行内色，React 的行内样式压得过任何 CSS 规则，必须先把行内 style 删掉（`NodePalette`、`PlatformNodeCard`、`PlatformContainerNode`、`NodeInspector` 四处），`spec.accent` 也从这几处解构里摘掉，避免留死字段。

保留的语义色：成功绿（`--a-3a5c45` 家族）、失败红（`--a-b03a2a`）、待处理琥珀（`--a-a26a12` / `--a-daa480`）。它们在深色主题里有对应的提亮版本，属于状态而不是装饰。

坑：React Flow 的 `<MiniMap maskColor>` 是写死的浅色 `rgba(247,249,252,.78)`，深色主题下缩略图会变成一块白板。改成 CSS 覆盖 `.react-flow__minimap-mask { fill: var(--minimap-mask) }` —— 表现属性优先级低于任何 CSS 规则，所以能压住；`--minimap-mask` 白 `rgba(247,249,252,.78)` / 深色 `rgba(9,10,12,.6)`。

### 外壳层次

白/深色主题把外层的「液态玻璃」换成实底：侧栏 `--app-sidebar` 比页面底深一档，右侧一条 `--app-line` 细线。画布底色在两套主题里去掉暖色渐变，改成 `--n-96`，节点卡片才立得起来。

### 自定义背景照片

> **已被 2026-11-12 的方案取代。** 本节描述的是「照片 + 薄纱 + 磨砂玻璃卡」的旧做法：全局 `blur(8px)`、满屏薄纱、深色下 `brightness(0.56)`，以及玻璃体系里的 `--glass-a` 配方。现在照片原图直出，可读性交给文字容器的局部羽化蒙版，详见 `docs/2026-11-12-背景照片文字压图改造.md`。下文只作历史记录保留。

- 入口：侧栏底部「外观设置」。
- 存本地：图片在 `createImageBitmap` 后压到 1800px、JPEG 0.86，再存 `localStorage`（`sl.appearance`），不上传服务器。
- 照片层：`<div class="app-photo">` 固定在 `.app-shell` 之前，`inset: 0`、`background-size: cover`，只做 `blur(8px) saturate(1.04)` 的轻微柔化 —— 模糊太重照片就退化成色块，看不出内容。上面叠一层 `--app-photo-veil-color`（浅色 30% 米白 / 深色 34% 近黑）当对比基线，深色主题再补 `brightness(0.56)`。
- 外壳：照片模式下 `.app-shell`、`.workspace` 全部透明，照片才透得出来。
- 透明度滑杆 0–100 写 `--app-photo-opacity`，默认 72%。

### 玻璃体系（照片模式）

改之前的问题：照片只铺在底层，卡片、侧栏、画布全是实底 token，等于几块不透明纸片叠在照片上，重叠处照片完全看不见，切页时一块透一块不透，很割裂。

改成一套统一的磨砂玻璃配方，定义在 `html[data-photo="on"]` 上：

| 变量 | 值 | 用途 |
| --- | --- | --- |
| `--glass-blur` | `blur(32px) saturate(1.1)` | 所有浮层用同一档模糊，磨砂粗细一致 |
| `--glass-edge` | `rgba(surface, 0.62)` | 玻璃边缘的浅色描边 |
| `--glass-lift` | `0 18px 44px rgba(shadow, 0.1)` | 统一投影，面板才「浮」起来 |
| `--glass-a` | `calc(0.9 - var(--app-photo-opacity) * 0.35)` | 卡片白度，跟着滑杆走 |
| `--glass-a-soft` | `calc(0.84 - var(--app-photo-opacity) * 0.3)` | 画布这类大面积容器的白度 |

`--glass-a` 是这套方案的关键：滑杆调高，卡片同步变透，照片更明显；调低则回到接近实底，小字更稳。默认 72% 时卡片 alpha ≈ 0.65。

覆盖范围：

- 对话页：侧栏、`.composer`、`.message-bubble`、思考折叠条、滚动到底按钮、`.new-chat-setup`。
- 工作流页：`.platform-canvas`（alpha 0.62，只留很薄一层）、`.react-flow` 背景透明（保留点阵）、`.platform-node` 比容器厚 0.1 保证节点小字、`.platform-palette` / `.platform-toolbar` / `.platform-run-strip` / `.platform-inspector` / `.platform-run-panel`。
- 工作台：改 `--wb-surface` 一个变量，所有卡片跟着走。
- 知识库、运行记录、Agent、MCP、验证报告、优化实验：各页主卡片按同一配方补一条。
- 对话页额外加一层 `radial-gradient` 中央柔光（`.workspace:has(.chat-workspace)::before`）：中间亮、四周透，标题和说明文字不会糊在照片的深色像素上。柔光只给对话页，工作台和画布不打，否则照片会被洗白。

踩坑：`platform.css` 在开发态比 `theme.css` 先加载（`document.styleSheets` 里索引 2 vs 5），同特异性的照片规则写在 `platform.css` 会被主题层里 `html[data-theme="…"] .platform-canvas` 反覆盖。所以照片模式规则统一收在 `theme.css` 末尾，`platform.css` 只留结构样式。

面板宽度同步从 366px 调到 400px（1180px 以下 344px），画布右上角工具组的 `is-shifted` 偏移跟着改成 420px。

## 四、已知取舍

- 深色下把品牌色当填充的按钮（新建 / 运行）单独压深了一档，其余强调色靠自动提亮。
- 照片模式下照片亮度本身会左右观感：壁纸的亮部区域，玻璃看起来接近白色；暗部才明显透出照片色。这是照片内容决定的，不是透明度没生效。
- 二级页面里还有一些内嵌小块（输入框、徽标、时间线卡片）保持原来的 0.9 左右白度，没有逐格玻璃化 —— 这些地方字号只有 10–11px，再透就压不住了。
