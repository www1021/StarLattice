# 2026-11-02 画布视觉与节点体系升级

## 背景与目标

对标 Coze / Dify / 魔搭 MCP 广场的编排体验，解决画布「不够精美、节点看起来少、连线缺少语义」三类演示问题。本轮只升级画布与节点体系，不改动既有运行内核的调度模型：画布仍只渲染顶层 DAG，容器内部继续在右侧检查器按列表编辑。

设计约束：

- 不新增占位节点，能拖上画布就必须能编译、能执行、能出现在 trace 里。
- `start` / `end` 只允许位于顶层且各一个；`start` 不覆盖「最近一次真实产物」，避免验证节点误验原始输入。
- HTTP 节点必须带 SSRF 防护，不能成为任意 URL 的外呼入口。
- 后端新增节点同时补齐 DSL、类型契约、执行器、节点类型规格与前端表单，保持一条链路。

## 后端与契约

- `server/platform/types.ts`：`NODE_KINDS` 与 `LeafNode` 加入 `start` / `end` / `knowledge` / `http`，定义 `HttpMethod` 与各节点结构。
- `server/platform/workflow/dsl.ts`：解析新节点；HTTP 方法白名单；请求头、超时、`topK` 等字段校验。
- `server/platform/workflow/compiler.ts`：
  - 顶层锚点唯一性校验；
  - `start` 禁止入边、`end` 禁止出边；
  - 锚点禁止嵌套容器；
  - `knowledge.topK` 1–20、知识库 ID 非空；
  - HTTP 方法、协议与超时范围校验；
  - 新节点引用收集（query / knowledgeBaseIds / url / headers / requestBody）。
- `server/platform/workflow/nodeTypes.ts`：新增四类节点规格与检查器字段。
- `server/platform/runtime/executor.ts`：
  - `start` 转发工作流输入且不更新 `lastArtifact`；
  - `end` 汇总输入映射；
  - `knowledge` 复用知识检索服务，未配置依赖时走 stub 且不伪造引用；
  - `http` 走注入处理器；stub 模式明确标记「未实际发送」，避免演示时产生外呼。
- `server/platform/runtime/httpNode.ts`（新增）：
  - 仅允许 http/https，拒绝带凭据 URL；
  - 拒绝 localhost、私网、链路本地、云元数据、`.local` / `.internal` / `.home.arpa`；
  - DNS 解析全部地址后再校验；
  - 手动跟随重定向最多 3 次且逐跳复检；
  - 响应体上限 256KB，超时 1–120s；
  - 轨迹只记录请求头键名，不记录值。
- `server/platform/runtime/liveHandlers.ts`：知识检索处理器同时接受工具节点与独立知识节点。
- `server/index.ts`：注册 `knowledgeNode` 与 `http` 处理器。

## 修复的缺陷

- **MCP 加入画布后节点丢失**：工作流异步加载会用旧定义覆盖刚补的节点。改为等待 `loading === false` 再应用待处理节点，并加幂等标记。
- **画布运行态错位**：边动画与节点耗时改为从 trace 聚合，容器内部步骤耗时归并到顶层节点；运行结束后按顶层节点状态着色。

## 已知限制

- 应用内隐藏浏览器不触发 `ResizeObserver`，导致进入时节点尺寸未测量、边短暂不渲染；在普通浏览器中正常，非业务缺陷。三档宽度（1440/1280/900）仅完成结构验收，未截图核对像素。
- 模板中的 Agent / 验证器需已在注册中心存在，否则保存或运行会报缺失；模板应用后会提示先检查。
- `http` 节点在 stub 模式不发起网络请求，仅 live 执行器会真实外呼。
- 一次全量并发测试出现 `routes.test.ts` 读取响应 JSON 的瞬时抖动，单文件与复跑均 95/95 通过，暂按环境抖动记录。
