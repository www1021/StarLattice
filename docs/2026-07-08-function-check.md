## 测试数据表结构

推荐先用一张宽表记录每次手工/自动化测试，字段如下：

今日验收指定字段已单独落表：编号、日期、模块、学科、年级、课题、输入摘要、引用数、耗时、输出摘要、总分、薄弱项、导出成功、是否进入成长档案、问题记录、结论。

| 字段 | 类型建议 | 说明 |
|---|---:|---|
| `id` | text | 测试记录 ID |
| `test_date` | date | 测试日期，例如 `2026-07-08` |
| `module` | text | 模块，例如新对话、知识库、虚拟课堂 |
| `component` | text | 组件/功能点，例如召回测试、教师输入区 |
| `input` | text | 测试输入 |
| `output` | text | 实际输出摘要 |
| `score` | number/null | 模块生成的评分，没有则为空 |
| `duration_ms` | number | 耗时，毫秒 |
| `citation_count` | number | 引用数 |
| `success` | boolean | 是否成功 |
| `issue_record` | text | 问题记录 |
| `severity` | text/null | P0/P1/P2/P3 |
| `evidence` | text | 截图、接口响应、文件路径或代码行 |
| `tester` | text | 测试人 |

SQL 草案：

```sql
CREATE TABLE module_test_records (
  id TEXT PRIMARY KEY,
  test_date DATE NOT NULL,
  module TEXT NOT NULL,
  component TEXT NOT NULL,
  input TEXT NOT NULL,
  output TEXT,
  score REAL,
  duration_ms INTEGER NOT NULL,
  citation_count INTEGER NOT NULL DEFAULT 0,
  success INTEGER NOT NULL CHECK (success IN (0, 1)),
  issue_record TEXT,
  severity TEXT CHECK (severity IN ('P0', 'P1', 'P2', 'P3') OR severity IS NULL),
  evidence TEXT,
  tester TEXT,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

选择理由：

| 维度 | 说明 |
|---|---|
| 贴合现有默认数据 | 虚拟课堂默认配置已经是“数学 / 初中 / 分数的意义” |
| 适合多智能体演示 | 学霸型、基础薄弱型、沉默型、调皮型、误解型学生 Agent 都能围绕“平均分、单位 1、四分之一”产生差异化反应 |
| 适合评价闭环 | 可评价教师提问、学生参与、误区处理、板书表达、课堂应变 |
| 适合知识库引用 | 可接入课程标准、教材片段、优秀课例，展示“证据先于结论” |
| 适合易班生态叙事 | 可沉淀为教案、说课、课堂报告、实习反思和成长档案，形成网络育人实践证据 |

建议演示输入：

```text
请以初中数学《分数的意义》为课题，帮我完成一次师范生实训：
1. 先给出教学重点和学生可能误区；
2. 进入虚拟课堂，围绕“平均分”和“单位 1”进行提问训练；
3. 课后生成课堂诊断报告，并沉淀到成长档案。
```

课堂发言脚本：

```text
请同学们把一个圆平均分成四份，涂出其中一份。
想一想：为什么它可以表示四分之一？
如果只是随便分成四块，还能不能叫四分之一？请说明理由。
```
